## 前端 Mock 双轨方案（web/）
为 `web` 目录实现了「纯前端 Mock 预览」+「真实前后端连调」双轨，对业务代码零侵入。

- 依赖：vite-plugin-mock 必须用 **2.9.8**（不是 3.0.2）。3.0.2 删除了 `localEnabled/prodEnabled/injectCode/createProdMockServer` 生产注入 API，只支持 dev。2.9.8 才有这些；其 `createProdMockServer` 位于 `vite-plugin-mock/es/createProdMockServer`。
- 关键文件：`web/.env.preview`(VITE_USE_MOCK=true，注意等号两侧不能有空格，否则 dotenv 不 trim，值变成 ' true')、`web/vite.config.ts`(用 loadEnv 读 mode，仅 VITE_USE_MOCK==='true' 时挂 viteMockServe)、`web/src/mockProdServer.ts`、`web/mock/auth.ts`(拦截 /api/auth/login|info|menus 等，admin/123456)。
- `build:preview` = `vite build --mode preview`；产物含 mock（client 端 XHR 拦截）。`vite preview` 即可纯前端预览。`dev`/`build` 不挂 mock，走真实后端代理。
- injectFile 必须显式设 `src/main.tsx`（v2.9.8 默认只找 main.ts|js，本项目入口是 main.tsx，否则注入静默失效）；injectCode 内 import 路径相对入口写 `./mockProdServer`（解析为 src/mockProdServer.ts），不是 `./src/mockProdServer`。

## pnpm 安装坑（本机）
pnpm 在本项目新增 devDependency 后，常不创建 node_modules 顶层软链、且 store 内嵌套依赖未链接，导致 vite.config.ts 报 ERR_MODULE_NOT_FOUND 或 mock 的 path-to-regexp 找不到。
修复：删掉 node_modules/.pnpm 虚拟 store 后重新 pnpm install（从缓存重链，快）。不要手动 ln -s（Windows 符号链接受限，junction 还会扰乱 node 的 .. 解析）。

## 已知遗留（非本次改动）
`pnpm build` 的 `tsc -b` 报 `src/layout/Layout.tsx:221` 类型错误：`storage.getSidebar()` 返回 `string` 不能赋给 `SidebarTone` 联合类型。属既有业务代码问题，与 Mock 无关；`pnpm dev` / `build:preview` 不受影响。
